# Review guide

![Spectator illustration: a document with a highlighted decision path.](/images/page-example.svg)

Use the review path that matches the change you want.

## Comment on the whole page

Use **Open a GitHub issue** at the bottom of the page. The draft includes the
source file and published URL.

## Comment on exact text

Select text in the article. Choose **Create issue** from the nearby toolbar. The
selected passage is quoted in the issue draft.

## Propose a correction

Choose **Edit page** from the selection toolbar or **Edit this page on GitHub** in
the document footer. GitHub opens the Markdown source and guides the change into a
pull request.

## Review checklist

- [ ] The proposal states the intended outcome.
- [ ] Current behavior and proposed behavior are not confused.
- [ ] Important tradeoffs are visible.
- [ ] Risks have a concrete response.
- [ ] Examples do not claim more than the evidence supports.
- [ ] Open questions identify the decision still needed.
